DESIGN SYSTEM REFERENCE
Swiss / InternationalTypographic Style
A reusable visual-design guide and implementation brief for digital products
CORE IDEA
Typography first. Precise grid. Generous whitespace. Neutral surfaces. Purposeful accents.
Purpose  A project-agnostic reference for applying Swiss / International Typographic Style to websites, web applications, dashboards, landing pages, and other digital interfaces.
How to reuse  Use the design principles as a baseline, then adapt the project context, routes, content, functionality, brand colors, and technical stack in the implementation prompt.
1. Overview
Swiss Style, also called the International Typographic Style, is a modernist graphic-design approach associated with clarity, objective communication, grid-based composition, sans-serif typography, and asymmetrical layouts. For digital products, it translates into interfaces that are orderly, readable, content-led, and visually consistent.
This is a general-purpose style guide, not a specification for a particular industry or application. It should be adapted to the content, audience, brand, and functional requirements of each project.
2. Core design principles
Clarity over decoration: Every visual element should help users understand content or take an action.
Grid-based structure: Use consistent columns, gutters, alignment, and layout rules.
Typography-led hierarchy: Distinguish content through size, weight, line height, and spacing.
Intentional whitespace: Create separation and emphasis through space rather than ornament.
Purposeful asymmetry: Use asymmetrical composition when it improves hierarchy, rhythm, or editorial interest.
Restrained color: Let neutrals carry the interface and use a limited accent palette deliberately.
Consistency: Use shared tokens and reusable components throughout the product.
Function before effect: Interactions, navigation, and data presentation must remain obvious and accessible.
3. General visual direction
Use a clean, editorial, modernist appearance rather than decorative or ornamental styling.
Prefer left-aligned text and ragged-right text edges for readability.
Use strong alignment and clear hierarchy instead of many competing visual treatments.
Keep layouts calm and structured while allowing selective asymmetry.
Treat color, borders, icons, and imagery as functional communication tools.
Do not confuse Swiss Style with extreme minimalism: retain every element needed for usability and understanding.

8. Interaction and accessibility
Use semantic HTML and maintain a logical heading hierarchy.
Make all interactive controls keyboard accessible with visible focus indicators.
Provide accessible labels and meaningful names for buttons and icons.
Ensure text and control contrast meets applicable accessibility standards.
Do not rely on color alone to communicate errors, status, or selection.
Provide loading, empty, error, disabled, and success states where relevant.
Use restrained transitions, commonly around 120–200 ms, without distracting motion.
Respect reduced-motion settings and ensure dialogs/menus are accessible.
9. Responsive behavior
Treat breakpoints as flexible guidelines; adapt them to the content and framework.
Mobile: stack content, simplify navigation, and keep key actions reachable.
Tablet: adjust columns and spacing; avoid forcing desktop layouts into narrow widths.
Desktop: use grid structure and whitespace to create hierarchy.
Wide screens: constrain content width so text and cards do not become excessively stretched.
Prevent horizontal page overflow and ensure form controls fit the viewport.
Transform dense tables into stacked layouts or deliberately scrollable regions when appropriate.
10. Common mistakes to avoid
Treating the style as simply a white background plus a sans-serif font.
Using too many accent colors or relying on bright color for every action.
Overusing uppercase labels, oversized headings, or exaggerated letter spacing.
Applying the same card grid to every type of content even when another layout is clearer.
Using decorative icons, shadows, gradients, or rounded pills without a functional reason.
Making layouts asymmetrical at the expense of usability.
Removing necessary details in the name of minimalism.
Ignoring keyboard access, contrast, responsive behavior, or empty/error states.

GRID AND SPACINGUse a responsive grid appropriate to the content; a 12-column desktop grid is a useful default. Use consistent gutters, align related elements to shared grid lines, and apply a reusable spacing scale such as 4, 8, 12, 16, 24, 32, 40, 48, 64, and 80 px. Use CSS Grid and Flexbox. Avoid arbitrary absolute positioning for primary structure. Keep content widths readable.
COMPONENTSCreate or refactor reusable components appropriate to this project, such as layout containers, navigation, page headers, buttons, form fields, cards, tables/lists, tabs, status labels, dialogs, notifications, empty states, and loading/error states. Use shared tokens and variants instead of duplicating styles.
Use thin borders, modest corner radii, minimal shadows, clear button hierarchy, visible focus states, consistent iconography, and restrained motion. Every visible control must perform its advertised action.
PROJECT-SPECIFIC PAGE REQUIREMENTSUse the page list and user goals supplied above. For every relevant page, preserve its purpose and working behavior. Define a clear hierarchy, primary action, content layout, responsive behavior, and necessary loading, empty, error, and success states. Use actual project data; do not invent records or metrics to fill empty space.
RESPONSIVE DESIGNAdapt the interface for mobile, tablet, desktop, and wide screens. Simplify navigation where needed, stack content when appropriate, keep controls within the viewport, and avoid horizontal page overflow. Do not merely shrink the desktop design; adapt it to the available space.
ACCESSIBILITYUse semantic HTML, logical heading hierarchy, labeled controls, keyboard-accessible navigation, visible focus indicators, sufficient contrast, meaningful icon labels, and accessible dialogs. Do not rely on color alone to communicate status. Respect reduced-motion preferences.
TECHNICAL CONSTRAINTSUse the existing framework, build setup, and styling conventions unless a justified change is necessary. Avoid unnecessary dependencies. Preserve routes, authentication, API calls, data models, and business logic. Do not expose secrets or private environment variables. Do not leave placeholder links or nonfunctional controls. Do not claim an operation succeeded unless it actually did.
VALIDATIONRun the available build, lint, and type checks. Inspect all changed routes and test relevant interactions. Check responsive layouts, alignment, typography, contrast, and empty/error/loading states. If browser preview or screenshots are available, inspect the rendered result and fix visible issues. Report accurately which checks were run and any remaining limitations.
DEFINITION OF DONEThe requested scope consistently follows the design system; typography, grid, spacing, and components are coherent; the accent is restrained; the interface is responsive and accessible; existing functionality remains intact; and available quality checks pass.
Final direction: create a professional, modernist, editorial interface defined by clear typography, precise alignment, structured grids, intentional whitespace, neutral surfaces, thin dividers, and purposeful color. Prioritize clarity and usability over decoration.
12. Suggested workflow for applying the style
Step 1 — Audit: Inspect the existing product, user needs, routes, content, and technical constraints.
Step 2 — Foundation: Define color tokens, typography, spacing, grid, and reusable component variants.
Step 3 — Implement: Apply the design system to the pages and flows in scope.
Step 4 — Review: Inspect actual rendered pages and correct hierarchy, spacing, alignment, and responsive issues.
Step 5 — Verify: Test interactions, accessibility basics, existing behavior, and available build/lint/type checks.

14. Final reference
Swiss / International Typographic Style is best understood as a system of visual decisions rather than a fixed theme preset. Its recognizable qualities come from consistent typography, grid discipline, alignment, hierarchy, whitespace, and restrained color. Adapt the exact palette, layout density, components, and content to each project's audience and purpose while preserving those principles.
